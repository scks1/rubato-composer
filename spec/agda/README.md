# Agda spec of Rubato's forms and denotators

This directory holds an Agda model of Rubato Composer's form and
denotator system as the Java core implements it (`org.rubato.math.yoneda`,
`org.rubato.math.module`, `org.rubato.base.Repository`). A generator
reads the registered forms and some denotators out of the running Java
code and writes them as Agda terms, and the Agda files prove what the
model says about them.

The Java code is the source of truth for behaviour. The theory
vocabulary (form, denotator, limit, colimit, power, address) comes from
the Rubato manual in `docs/manual.tex` and from Mazzola, Noll and
Lluis-Puebla, *Perspectives in Mathematical and Computational Music
Theory* (p. 92 lists the form types). The table of departures below
names each place where the Java code does something the theory does
not say, and what the model does there.

Agda 2.6.3 with only its primitive library (`Agda.Builtin.*`), no
standard library. Every module uses `--safe --without-K`.

## Running

```
cd upstream && . ../env.sh            # JDK 21 on this VM
mvn -B -o verify                      # or ant dist; builds the -all jar
spec/agda/run-checks.sh [log-dir]
```

`run-checks.sh` compiles the four Java programs against
`java/target/rubato-composer-0.1.0-SNAPSHOT-all.jar` (override with
`JAR=`), runs the three generators and fails if their output differs from the
committed `Generated.agda`, `GeneratedAddresses.agda` and
`GeneratedCertificates.agda`, runs the probe, typechecks the twenty positive
modules from a clean state (it deletes `*.agdai` first), runs
`check-certificate.sh GeneratedCertificates.agda`, and typechecks
each adversarial file, which passes only when Agda rejects the file with
the expected text at a location inside that file. `SKIP_JAVA=1` skips
the Java steps. `AGDA=` picks the Agda binary.

To refresh `Generated.agda` after a change to the registered forms, run
the generator by hand (see the script) and commit the new file together
with the change; the proofs in `GeneratedChecks.agda` then say whether
the new forms still agree with `Registry.agda`.

## What is modelled

- **Forms** of the five Java types (`Yoneda.SIMPLE` to `Yoneda.LIST`):
  simple over a module, limit and colimit with coordinate form names and
  optional labels, power and list over one coordinate form. A form refers
  to its coordinates by name, so recursive forms (MacroScore, SoundScore,
  FMSet, Modulators) are entries in a repository.
- **Repositories** as lists of `name ≔ body`, with three checkable
  invariants: names unique (`uniqueB`), every referenced form defined
  (`closedB`), labels either absent or one per coordinate (`labelsOkB`).
- **Modules** Z, Q, R, C, Z/n and Rⁿ, with Java's element invariants:
  Z/n values below the modulus and Q denominators positive.
- **Zero-addressed denotators** of each type, with an optional name.
- **Addressed simple coordinates** (`Addresses.agda`): over Z, Q and R, a
  coordinate at the address Cᵐ in the module Cⁿ is an affine map Cᵐ → Cⁿ
  held as a matrix and a shift, as `ZFreeAffineMorphism`,
  `QFreeAffineMorphism` and `RFreeAffineMorphism` hold it. Address change
  along f : Cᵏ → Cᵐ composes by matrix product, evaluation at a applies
  the map, and the constant map from the zero module C⁰ is a 0-column
  matrix with a shift. Topos of Music I, section 6.2.1 (p. 53) and 6.2.2
  (p. 54).
- **Java's order on denotators** (`cmpDen`): form, then denotator name,
  then content, following `Denotator.compareTo`, `Form.compareTo`,
  `NameDenotator`/`NameEntry`, the morphism-map `compareTo` methods and
  each `ModuleElement.compareTo`, apart from the overflow in D5.
- **Well-formedness** `E ⊢ d ∶ F`: d's form is F, F is registered,
  a simple element lies in F's module, a limit has exactly one coordinate
  of the right form per factor, a colimit's index names a cofactor and its
  factor has that cofactor's form, a power's elements have the coordinate
  form and are strictly ascending under `cmpDen` (the TreeMap order), and
  a list's elements have the coordinate form in any order.

## What is not modelled

- Addressed denotators of the compound types (limit, colimit, power,
  list), addresses other than the free modules Cᵐ over Z, Q and R, and
  module morphisms that are not affine (D4). `ExportAgda` still refuses
  a denotator that is not null-addressed.
- Java's `changeAddress(Module)`, which changes along
  `CanonicalMorphism.make` (D18).
- Address order and equality: since the commit "Fix denotators at
  non-zero addresses" Java's `equals` and `compareTo` compare addresses
  first when they differ; the zero-addressed `cmpDen` has no address to
  compare.
- Module morphisms, `ModuleMorphism` coordinates and every module other
  than the six above (polynomial rings, product rings, direct sums,
  strings). They appear as `otherM` with no elements.
- Operations on denotators: union, intersection, `Denotator.map`, the
  logeo package, path access with `int[]` paths, Scheme.
- Denotator name structure: names are flat strings (D16).
- Saving and loading XML, the rubettes, the UI.
- Mutation. Java denotators are mutable (`setFactor`, `appendFactor`);
  the model describes values.

## What is proved

Proofs by computation (`refl`) on concrete terms are marked (c);
the rest are proofs for all inputs.

`OrderedSets.agda`, for any comparison `c`:
- `insert-asc`, `fromList-asc`: if `c` is flip-symmetric
  (`c b a ≡ flipO (c a b)`), TreeMap-style insertion keeps a list
  ascending, so `fromList` always returns an ascending list.
- `head-below-all`, `no-duplicates`: if `c`'s `lt` is transitive, the
  head of an ascending list is below every later element, and so no two
  elements of an ascending list compare `eq`.
- `ascB-sound`, `ascB-complete`: the boolean test agrees with `Asc`.

`Prelude.agda`: `==ˢ-sound`, `==ˢ-refl` (string equality), and
flip symmetry of the exact Nat and Int orders (`cmpNat-flip`,
`cmpInt-flip`).

`Forms.agda`:
- `sound`: `check E d F ≡ true` implies `E ⊢ d ∶ F`.
- `complete`: `E ⊢ d ∶ F` implies `check E d F ≡ true`.

`Registry.agda`:
- (c) `handEnv` satisfies the three repository invariants.
- (c) Note has 5 factors with labels onset, pitch, loudness, duration,
  voice; SoundNote has 6 factors with Modulators at index 5; no form
  named Layer is registered (upstream 376ff94 removed Layer from
  SoundNote; known-bugs 9ffdfc9 made SoundNoteGenerator follow it).
- (c, through `sound`) a three-note Score, a two-level MacroScore, a
  SoundScore whose note has a modulator, an IntegerOrReal colimit, the
  empty Score and a BooleanList with repeats are well-formed.
- (c) `check` rejects a Note with four coordinates, a coordinate of the
  wrong form, a colimit index outside the cofactors, a colimit factor of
  the other cofactor's form, a Score with a repeated note, an unsorted
  Score, a Z/2 value 2, a rational with denominator 0, a real where Z is
  required, and a denotator of an unregistered form.
- (c) `fromList cmpDen` turns n2, n0, n2 into n0, n2, as Java's
  PowerDenotator does (probe P3); names sort before content (P4); a list
  that is a prefix of another is greater (P8).
- `cmpR-not-flip-symmetric`: Java's real order is not flip-symmetric,
  with NaN and 1.0 as the counterexample, so `fromList-asc` does not
  apply to sets of reals. (c) `cmpR nan nan ≡ gt`,
  `cmpR 0.0 -0.0 ≡ eq`.
- `integerSet-sorted`: building an IntegerSet with the exact integer
  order always gives an ascending list.

`GeneratedChecks.agda`:
- (c) `javaEnv`, the 48 forms Java registers, satisfies the three
  invariants.
- (c) `registry-agrees`: for each of the 22 hand-written forms,
  `javaEnv` holds the same body.
- (c, through `sound`) eight denotators built by Java are well-formed: a
  Score (inserted out of order; one note named), the Note Java padded
  from three coordinates, a MacroScore with a satellite, the three-level
  SoundScore from `SoundNoteGenerator.createMultiLevelSoundScore`, an FM
  SoundNode from `createFMNodeDenotator` (model "Double modulator"), a
  GeneralScore holding a Note and a Rest through the NoteOrRest colimit,
  an Envelope list with a repeated node, and a Complex.
- (c) the IntegerSet Java stores for 1, MIN_VALUE, 0 and the RealSet
  Java stores for NaN, NaN, 1.0 are rejected (D5, D6).

`adversarial/`: each file states something false and Agda rejects it.
ShortNote, DuplicateNote, ColimitIndex and UnregisteredForm try to prove
ill-formed denotators well-formed; JavaNaNSet and JavaOverflowSet try the
two Java sets above; SoundNoteLayer claims SoundNote has 7 factors;
RealFlipSym claims flip symmetry of `cmpR` at NaN and 1.0;
ConstructorArity builds a Note derivation with no coordinates directly
from the constructors.


`Addresses.agda`, for any ring given with the laws in `Laws`
(associativity and commutativity of +, 0 + a = a, associativity of ·,
0 · a = a · 0 = 0, both distributive laws):
- `compose-apply`: the composition of affine maps by matrix product is
  precomposition, `apply (compose f g) v ≡ apply f (apply g v)`.
- `at-is-change`: evaluation at a is the address change along the
  constant map 0 → Cᵐ with value a, followed by evaluation at the one
  element of the zero module (Topos I, pp. 53–54).
- `change-functorial`: changing along f and then along g is changing
  along f ∘ g.
No ring instance proves the laws. Int satisfies them, but the proofs for
the hand-written `_+ℤ_` and `_*ℤ_` are not written; the unreduced
fractions of `ℚ-ring` satisfy them only up to cross-multiplication;
floats do not satisfy them. The theorems therefore say what the matrix
model computes, and the checks below say that Java computes the same.

`AddressChecks.agda` (c): for each of the 30 exported address changes,
Java's values of `d.changeAddress(f)` at the zero element and at 2·eᵢ
for each basis vector equal both the model's matrix composition and the
precomposition d(f(x)); for each of the 15 exported evaluations, Java's
`d.at(a)` equals d(a) and the change along the constant with value a.
Three Z cases (and three each over Q and R) change along a constant from
the zero module, which Java got wrong before the commit "Fix denotators
at non-zero addresses". `adversarial/AddressWrongValue.agda` shows that a
wrong value fails the check. The R cases use dyadic values, so Java's
doubles and Agda's floats compute them exactly.

`Counterpoint.agda` restates the definitions of
`org.rubato.math.counterpoint` (CCW = Agustín-Aquino, Junod and Mazzola,
*Computational Counterpoint Worlds*, 2015) over Nat with reduction mod 12,
and proves by computation:
- `all-strong`: each of the six class representatives 64, 68, 71, 75, 78
  and 82 is strong: exactly one of the 48 affine maps T^t·u exchanges its
  consonances with its dissonances, and only the identity fixes them
  (CCW Def. 2.3, p. 8).
- `polarities`: the map listed for each class is that exchanging map, so
  it is the polarity. The same six values are asserted in Java by
  `DichotomyTest.testPolaritiesOfTheSixClasses`; only class 82's, T²·5,
  is printed in CCW (Example 2.2, p. 8).
- `involutions`, and pointwise `involution-at`: each polarity is an
  involution; `dissonant-image`: it sends each consonance to a dissonance.
- `induced-polarities`: for every class and every cantus firmus x₀ the
  induced polarity p_x₀[ε] = T^{x₀(1−u)+ε.t}·u (CCW Prop. 2.2, p. 11)
  keeps x₀ and exchanges consonant and dissonant points of Z12[ε], on all
  144 points; `translations-preserve`: cantus-firmus translations preserve
  consonance of x + ε.y.
- For (K/D) at ξ = ε.9 and g = T^{ε.8}·(5 + ε.4) (CCW Example 2.5,
  pp. 15–16): `xi-outside` (ξ ∉ gK[ε]), `deformed-polarity` (p₀[ε] is a
  polarity of the deformed dichotomy gK[ε]/gD[ε], the sense in which a
  contrapuntal symmetry carries consonance and its polarity over), and
  `intersection-56`.
That 56 is the maximum over all g is not proved in Agda; the Java tests
check it against a search of the whole group.
`adversarial/CounterpointNotStrong.agda` claims CCW's X2 = {0,1,3,7,8,11}
is strong (it is autocomplementary but fixed by T⁸·5);
`adversarial/CounterpointWrongSymmetry.agda` claims p₀[ε] is a polarity
of the deformation by T^{ε.8}·(1 + ε.4), which leaves ξ outside and also
meets K[ε] in 56 points, so only the polarity condition rules it out.

`Global.agda` writes out the seven triadic and seven tetradic degree
charts of C major (Topos of Music I, section 13.4.2, p. 262, and Ex. 21,
p. 275) and defines the nerve as the non-empty sets of degrees whose
charts share a tone (section 13.2.1, p. 253). It proves by computation:
- `strip-exactly`: over all 128 sets of degrees, a set is a simplex of
  the triadic nerve exactly when it lies inside one of the seven tone
  stars {I, IV, VI}, {II, V, VII}, {I, III, VI}, {II, IV, VII},
  {I, III, V}, {II, IV, VI}, {III, V, VII}; `strip-f`: the face counts
  are 7, 14, 7; `strip-euler`: V + F = E, so the Euler characteristic
  is 0.
- `boundary-size` and `boundary-is-fifths`: the edges in exactly one
  triangle are the seven edges of the fifth sequence
  V–I–IV–VII–III–VI–II–V; `strip-edges-pseudo`: every edge lies in one or
  two triangles.
- `torus-exactly`: the tetradic nerve is exactly the complex generated by
  S1–S7 of Agustín-Aquino and Mazzola (J. Math. Music 14, 2020, section
  6); `torus-f`: face counts 7, 21, 21, 7; `torus-euler`: Euler
  characteristic 0; `k7`: its 1-skeleton is the complete graph on the
  seven degrees; `torus-triangles-pseudo`: every triangle lies in one or
  two tetrahedra; `torus-cycle`: consecutive tetrahedra of the cycle
  S5, S7, S2, S4, S6, S1, S3, S5 share a triangle.
Orientability and homology are not proved in Agda; `NerveTest` checks
them in Java.
`adversarial/GlobalWrongTriangle.agda` replaces the star of C by
{I, II, III}; `adversarial/GlobalStripIsK7.agda` claims the triadic
1-skeleton is K7; `adversarial/GlobalEulerOne.agda` claims the strip has
Euler characteristic 1.

`Harmony.agda` writes out the triadic and tetradic degree chords of C
major again and decides by evaluation:
- `triadic-cadences` and `tetradic-cadences`: the minimal cadential sets
  (Topos I section 26, Def. 87, pp. 453-461) are {VII}, {II,III},
  {II,V}, {III,IV}, {IV,V} for triads and {V}, {VII}, {I,II}, {I,IV},
  {II,III}, {III,IV} (J5, J6, J1-J4 of Blues for Alice, p. 3) for
  seventh chords; `II-V-cadential`: {II7,V7} is cadential (and not
  minimal, since {V7} is).
- `row` checks one row of a quantum table (Topos I section 27.1.5, Def.
  88, p. 469; Agustin-Aquino and Mazzola 2019, Algorithm 1): the map is a
  modulator, the cadence is minimal, the orbit of the cadence's tones is
  the given quantum, its trace is rigid under the 23 non-identity TI
  maps, the pivots are the given degrees and the covering flag is the
  given one. `schoenberg-C-F` (triads, C to F, x ↦ 9 − x, pivots {II, IV,
  VII}), `table1-tr1-V`, `table1-tr1-VII` (an asterisk row),
  `table1-tr7-V`, and `omitted-tr3-VII`, a row that Def. 88 gives and
  Table 1 omits.
- `R42-involution` and `R42-commutes-T5` over all 60 seventh chords,
  `R42-IV-II` (Fmaj7 to Dm7, with their tones the degree tetrads IV and
  II), and `P42-I-II` (P42 of I7 in K is II7 in K − 2, for all twelve
  keys).
The group order of PLRQ (Cannas, Antonini and Pernazza 2017, Thm. 1) is
checked in Java only (`PlrqTest`).
`adversarial/HarmonyTriadicIIVI.agda` puts {II,VI} in place of {II,V};
`adversarial/HarmonyOmittedRowNotQuantized.agda` claims the omitted Tr3
row fails; `adversarial/HarmonyR42IVtoIII.agda` claims R42 sends IV7 to
III7; `adversarial/HarmonyP42IsT8L42.agda` claims P42 equals T8 L42 on
every chord (they agree on major sevenths only).

`Performance.agda` covers the discrete and finite parts of the
performance package (`org.rubato.math.performance`):
- `leaves-pos`, `edges-size` and `not-own-daughter`: for every stemma
  shape, at least one leaf, edges + 1 = nodes, and no node among its
  own daughters (Topos II Defs. 106-107, p. 628). A rose tree is finite
  and a tree by construction, so these are the conditions of Def. 107
  that are left to prove. `Stemma.validate` checks the same conditions
  on the Java object graph, where sharing and cycles can occur.
- `fig38-5-nodes`, `-edges`, `-leaves`, `-layers`: the stemma of Fig.
  38.5 (p. 629) has 21 nodes, 20 edges, 4 leaves and 7 operator layers,
  the counts `StemmaTest.testFig385Counts` checks in Java.
- `three-bars-minutes`, `three-bars-seconds` and `linear-onsets`: step
  tempi (Example 49, p. 552) give exact rational onsets by eq. (33.1);
  bars of four quarters at M.M. 60, 90 and 120 end at 13/90 minutes,
  26/3 seconds, and equal bars at one tempo give onsets in arithmetic
  progression. A tempo of 0 cannot be written: `Tempo` carries a proof
  that its numerator is positive.
Polygonal, linear, exponential and sine tempi, the fields and the
operators need logarithms or real analysis and are checked in Java only.
`adversarial/PerformanceFig385FiveLeaves.agda`,
`PerformanceFig385SixLayers.agda` and `PerformanceEdgesEqualNodes.agda`
miscount Fig. 38.5; `PerformanceSelfDaughter.agda` claims a stemma is
its own daughter; `PerformanceZeroTempo.agda` writes a tempo of 0;
`PerformanceStepOnsetWrong.agda` performs every bar at M.M. 60.

`Gestures.agda` covers the finite parts of the gesture package
(`org.rubato.math.gesture`):
- `f-ok`, `g-ok`, `gf-ok`, `id-path3`, `swap-arrow` and `cycle-to-loop`:
  the morphism law (tails and heads preserved, Topos III 61.1, pp.
  913-916) decided on six small cases, including one composite.
- `Ω-arrows` and `Ω-shape`: the subobject classifier built from the
  closed sieves on the site t, h : V → A (Topos IV J.1, p. 1460) has 5
  arrows, one loop at false, one arrow each way and two loops at true.
- `hom-Ω`, `sub-counts`, `yoneda-arrow` and `yoneda-point`: on eight
  small digraphs the maps into Ω and the subdigraphs are equinumerous
  (1, 2, 5, 3, 13, 7, 7, 31), maps from the arrow digraph count arrows
  and maps from the point count vertices.
- `VII-arrows`, `ΓC-size`, `V⇒I`, `IV⇒V-vertices`, `IV⇒V-extra` and
  `IV⇒V-covers`: Example 69 (p. 930) on the merged 16-arrow digraph.
  V ⇒ I equals I ∪ IV ∪ VI as printed; IV ⇒ V has the vertices and
  arrows of III ∪ V plus VII's loop at 11, so the printed equation fails
  (GESTURES-SPEC E5). The unmerged 17-arrow digraph is checked in Java
  only.
- `faces-*`: Def. 112's face coefficients (p. 969), sign head minus tail,
  for ten digraphs: binomial differences on the up-arrows, 0 on the loop,
  the 2-cycle and Ω, (2, 1, 1) on the fork and (2, −3, −3) on the join.
Each fact is decided by evaluation for the listed digraphs; no general
theorem (for example that composites of morphisms are morphisms) is
proved. Curves, metrics, hypergestures, the Escher exchange and the
path-algebra examples need real numbers or linear algebra and are checked
in Java only. `adversarial/GesturesBookIVimpliesV.agda` states the book's
IV ⇒ V; `GesturesOmegaFourArrows.agda` gives Ω four arrows;
`GesturesEx76Sign.agda` uses Example 76's printed sign;
`GesturesPath2Ends.agda` claims the path's face is g(2) − g(0);
`GesturesReversedArrow.agda` claims swapping an arrow's ends is a
morphism; `GesturesHomSubMismatch.agda` counts 12 maps from the path into Ω.

`Monteverdi.agda` covers stage 7 (MONTEVERDI-SPEC):
- `candidates-exact`: of the 576 maps e^{ε.t}∘(u + ε.v) in H, the 192 in
  `CANDS` are exactly those under which the induced polarity at 0,
  (5x, 5y + 2), exchanges gK[ε] and its complement (CCW Def. 2.5,
  p. 14).
- `syms-0` … `syms-9`: for each consonance k, the maps in `CANDS` that
  leave ε.k outside gK[ε] and meet K[ε] in the largest number of points
  are the listed sets (5, 2, 2, 1, 5 and 2 maps for k = 0, 3, 4, 7, 8, 9).
- `cards-*`: the cardinality columns of the Confitebor, Ma tu, Io mi son,
  Laudate and both Gloria tables (pp. 8-11), with each step's set read as

polarity of Example 3's.

### Agda certificates (Certificates.agda, GeneratedCertificates.agda)

Each certificate is a definition whose type is a claim of `Certificates.agda`
and whose body Java wrote; Agda accepts it only if the claim holds under the
Agda definitions, which were written by hand from the paper apart from the
Java code. Positive all-interval certificates give one witness pair per
interval class and an absurd clause above ⌊n/2⌋; negative ones refute the
smallest missing class by one absurd clause per ordered pair. Ex. B.3 is
proved for all 36 keys, vacuously for the 12 natural-minor keys. The seven
`adversarial/Certificates*.agda` files forge certificates: a wrong witness
pair, a positive claim for {0, 1, 2, 3}, a refutation for an all-interval
set, a missing class, a leading tone in the natural-minor V, a vacuous
proof in C major, and F sharp in C major.

## Stated but not proved

- `cmpDen` is flip-symmetric or has transitive `lt` on well-formed
  denotators. It is false in general because of NaN (proved above for
  `cmpR`), and for NaN-free reals it needs facts about floating-point
  subtraction that Agda's primitive floats do not expose. So the model
  does not prove that Java-built power denotators are duplicate-free; it
  checks ascending order on each concrete set, and `no-duplicates` gives
  duplicate-freedom for any order whose `lt` is transitive.
- The model's `cmpDen` matches Java's `compareTo` in sign. This rests on
  reading the Java code and on probe P3, P4, P8 and P11, and on the
  generated Score being accepted in the order Java stored it; it is not
  proved against Java.
- `ExportAgda.java` prints the Java values faithfully. The script checks
  that its output is stable, and `registry-agrees` compares it with the
  hand-written forms, but the printer itself is unverified Java.

## CI

`.github/workflows/ci.yml` has an `agda-spec` job: it builds the jar
with `mvn -DskipTests package`, installs `agda-bin` and `libghc-agda-dev`
from Ubuntu 24.04's archive (Agda 2.6.3, the version used here), runs
`run-checks.sh` and uploads its logs. Since stage 10.2 that run also diffs
`GeneratedCertificates.agda` against `gen/ExportCertificates.java`,
typechecks it and runs the seven certificate adversarial files; on this VM
the whole Agda part takes about 44 s with `SKIP_JAVA=1`. The job has not run on GitHub: the
branch is local. Package names and the prim-library location come from
this VM's notes on the Ubuntu noble packages, not from a runner.
